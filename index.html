Client 01 · Browser

Web SPA

  • Dual-mode session auth — Sanctum stateful cookies for the browser, with the same login endpoint branching to issue a Bearer token for non-browser clients (detected via Sanctum's own frontend-origin check), so one auth endpoint serves two fundamentally different client types without duplicating logic.
  • Layered RBAC — enum-based roles (client / admin / super admin) combined with spatie/laravel-permission, enforced via middleware and policies on the backend and mirrored in the React UI.
  • OAuth via Socialite — Google, Facebook and GitHub sign-in unified into the same session flow.
  • Real-time messaging over Reverb and Echo, with per-participant read receipts and policy-enforced conversation privacy.
Client 02 · Native (GabApp)

Desktop client

  • Interoperability by contract replication, not reinvention — rather than build a separate backend surface, the desktop app replicates the web app's exact REST, WebSocket (Pusher protocol) and WebRTC signaling contracts, verified end-to-end against the real backend at each build phase.
  • Custom Pusher-protocol client written from scratch over raw websockets, because the standard Python client (pysher) can only listen — it can't send the client-* whisper events that WebRTC call signaling requires.
  • 1:1 video and voice calling via aiortc, mirroring the browser's peer connection logic exactly — including matching an ICE-candidate queuing behavior needed because aiortc doesn't trickle ICE the way the browser does.
  • One asyncio event loop for everything (qasync) — GUI, WebSocket client and WebRTC media all share a single loop instead of juggling threads.
  • Zero-config hardware handling — camera and mic are auto-detected at runtime, including disambiguating Windows' merged microphone/speaker PnP class, so a packaged build runs unmodified on machines with unknown hardware.
  • Frictionless sign-up handoff — "Sign up" opens the web app's registration page in the system browser, then auto-logs the desktop app in via a one-shot local loopback callback server, so there's no native registration form to keep in sync.
  • Standalone Windows build packaged with PyInstaller — no Python install required on target machines.
